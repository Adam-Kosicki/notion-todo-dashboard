# Domain Context & Ubiquitous Language

This document defines the core business vocabulary and domain models for the **Backburner** system. It is strictly a glossary of domain concepts without implementation details.

---

## 1. Core Entities

### Capture / Raw Thought
An unclassified string or snippet of text or voice entered with zero friction by the user before any classification, scheduling, or tagging takes place.

### Item
The abstract parent concept for anything captured into Backburner. An item is classified into one of four concrete types: **Task**, **Goal**, **Project**, or **Note**.

### Task
A distinct, actionable unit of work that can be executed and marked complete in a single session or straightforward sequence of steps (e.g., "Schedule car inspection").

### Goal
A high-level desired outcome or state over a medium-to-long-term horizon that is not directly actionable as a single checkbox (e.g., "Gain 15 pounds in 2026"). A Goal decomposes into Milestones and actionable Child Tasks.

### Project
A multi-step initiative with a defined scope, end state, and collection of interrelated Tasks and Milestones (e.g., "Launch version 1.0 of Backburner").

### Note
A piece of reference information or idea with no required direct action (e.g., "Gemini API rate limits for 1.5 Pro").

### Milestone
A measurable intermediate checkpoint within a Goal or Project used to evaluate progress over time.

---

## 2. Friction & Lifecycle Dynamics

### Capture Friction
The cognitive barrier to recording an idea when an interface demands immediate decisions regarding lists, tags, priorities, recurrence, or deadlines before saving.

### Organization Friction
The cognitive burden caused by uncurated task lists accumulating dozens of stale, un-prioritized items, turning the task list into an overwhelming "task graveyard".

### Goal Decomposition
The process of transforming an ambiguous, long-term aspiration into structured, measurable milestones and actionable daily/weekly routine tasks.

---

## 3. Priority & Attention Concepts

### User Priority
The explicit priority level assigned directly by the human user (`P0` Urgent, `P1` High, `P2` Normal, `P3` Someday).

### AI Priority
An advisory priority level calculated by contextual LLM analysis based on real-world constraints, implied deadlines, and user commitments.

### Effective Priority
The composite runtime priority determined by blending User Priority, deadline proximity, staleness, and AI suggestions.

### Attention Score
A continuous numerical value computed by the deterministic **Attention Engine** to quantify how urgently an item requires user or system attention.

### Staleness
A measure of elapsed time since the last meaningful interaction, progress update, or completion event on an active item.

### Ignored Count
The number of consecutive proactive nudges or notifications for an item that were delivered but dismissed or left unacknowledged by the user.

---

## 4. Engagement & Interaction

### Nudge
A proactive prompt or notification generated by the system to re-engage the user on an item. A nudge can be an acknowledgement request, a status query, or a decomposition prompt.

### Reassessment
A conversational or structured check-in where the system asks the user to confirm whether a stale or neglected item remains relevant, should be rescheduled, or should be abandoned.

### Escalation Policy
A set of rules defining how nudge frequency, tone, and delivery channel change when an item is repeatedly ignored (e.g., escalating from passive review to an urgent reminder).

### Attention Layer
An architectural pattern where Backburner operates not as a standalone task database, but as an intelligent supervisor sitting above existing task-management systems to provide attention scoring, staleness detection, and proactive re-engagement.

### Adapter
A connector module enabling Backburner's Attention Layer to synchronize task state, receive captures, and push notifications to external task-management systems (such as Super Productivity, Google Tasks, Microsoft To Do, or mobile OS notifications).
